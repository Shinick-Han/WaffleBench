# Inspection v4 boundary

Separate authored-synthetic study. Hypothesis: a supervised class-conditional Gaussian-mixture DOI model (`inspection_v4/model.py`) on the same seven public features and the same historical candidate DOI labels beats the strong current algorithm, a freshly fitted CB400 with the `route_full_gamma` planner. No v1/v2/v3 source, protocol, receipt, evidence or UI is modified. The v1 generator, sensor, retry rule and CU costs, the v3 harness and the v1/v2/v3 policies are reused unchanged; v4 owns only its run matrix and model-API plumbing (`inspection_v4/cli.py`), without monkeypatching and without the v3 compiled predictor for mixtures (an immutable snapshot predictor calls `inspection_v4.model.predict`).

Fresh seeds (`inspection_v4/protocol.json`), five scenarios `stationary, novel_cluster, low_contrast, nuisance_heavy, process_shift` with index j: train 60 = 12 per scenario `8000+j*20+i`; calibration 20 = 4 per scenario `8100+j*10+i`; development 40 = 8 per scenario `8200+j*100+i`; test 120 = 24 per scenario `9000+j*100+i`. Seed 9800 is reserved for a separate live demonstration and is not part of any split. `check_splits` runs before any lot is generated or read; it rejects every v1/v2/v3 reserved seed (train, validation, test and all v2/v3 split tables), the live reserve, cross-split duplicates, unknown scenarios and unbalanced splits. `splits.train_seeds`/`test_seeds_by_scenario` are synchronized with `v2_splits` so the reused v2 training and calibration guards apply; `v4_splits` is omitted. The generator receives a view without train seeds because the v1 stationary-only train request rule is superseded by `check_splits`; physics are identical.

Models, all frozen (no online updates; the harness model API rejects updates): logistic (v1 numerics and `model` settings, v2 guards on true seed/scenario pairs), CB400 (depth 6, learning rate 0.06, 400 iterations, 2 threads), and Gaussian mixtures diag 4/3, diag 8/6 and full 4/3 positive/negative components (max_iter 200, tol 1e-5, reg_covar 1e-3, seed 2026100404). Every model uses the same 60 training lots; each mixture gets identity, Platt and temperature calibrations from the same 20 calibration lots. Every model runs `learned` and `route_full_gamma` (gamma 1), candidate-only, 360 CU only.

Before any test lot exists, the primary candidate is the gaussian_mixture variant with the highest development mean true confirmed DOI, then lower mean spent CU, then variant ID; baselines are never eligible. Primary comparator `cb400_route_full`, target relative gain 5% with a positive lower bound of the paired, scenario-stratified lot bootstrap (2000 replicates, seed 2026100404). Secondary: versus `logistic_learned` and versus the same mixture model's `learned` variant; candidate-site classification AP, recall, precision, Brier, ECE and log loss overall and per scenario; per-scenario failures against the primary comparator. Matched cost to 5 true DOI on the same 360 CU ledgers is supplementary only and carries no 30% saving claim. All variants, including failed hypotheses and baselines, are saved. Software CPU/wall time is reported separately from equipment CU.

CLI `python -m inspection_v4.cli develop|freeze|campaign|report --root DIR` prints JSON and writes JSON progress files; `develop` needs a new root, `campaign` refuses a started campaign (no silent resume) and writes `FAILED-<stage>.json` on failure. `freeze` records v1/v2/v3/v4 source, protocol, contract, `pyproject.toml` and `uv.lock` hashes, frozen config/models/development/lot-manifest hashes, model hashes and lot receipts; `campaign` re-verifies all of them before generating test lots. Previous held-out evidence motivates the hypothesis only and supplies no fitting or selection data. The coordinator runs the real campaign after M5 authorization; workers do not.
